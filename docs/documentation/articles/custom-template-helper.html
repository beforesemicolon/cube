Custom Template Helper

Cube template most powerful detail is the fact it calls functions when it finds them. If a function is not used for event listener, it is considered a dynamic value which are functions that return what needs to be rendered or evaluated.

This means that we can create any function that handles a repetitive or complex logic in the template.

Few Rules

In order to improve the success of your helpers it is important to be familiar with the html API and how Cube component works. Besides that, the rules are simple:

  • Keep your helpers pure: helpers are reusable single unit functions that can be used anywhere. Unless it is something specific for your application, keep helpers pure and independent.
  • Only rely on templating helpers: don't rely on Cube component lifecycles, state helpers, or others component specific helpers. These only work inside a component which will limit where your helpers can be used and how.

Example 1: suspense helper

We can create a simple helper that will allow us to render according to an asynchronous action.

const suspense = ( asyncAction, loading = html`

loading...

`, failed = (msg) => html`

` ) => { asyncAction() .then((content) => { content.replace(loading) }) .catch((err) => { failed(err.message).replace(loading) }) return loading; }

The helper takes an asynchronous function or one that returns a promise, then an optional html instance to render while promise is resolving followed by a callback for error that take the error message and returns an html instance to render.

The first thing it does is return the loading html instance. This is because the Cube template system is synchronous therefore something needs to be returned to render. Then, it waits for things to resolve or fail to use the amazing html update method to replace the rendering loading html instance.

With this simple helper you can render things based on asynchronous action which is pretty amazing. This is because Cube templating system is function oriented which allows you to use functions as data in the template to perform amazing calculations and rendering.

Example 1: drag and drop helper

This is where Cube template shines. You can keep templates clean by offloading all related logic to a function that manipulates it. Let's look at a simple drag-and-drop example

First, the draggable helper:

const draggable = (content) => { const id = crypto.randomUUID(); const handleDrag = (event) => { event.dataTransfer.setData("text", id); } return html`
${content}
`; }

Here we are simply wrapping the provided content in a div with draggable="true", an id we randomly generate and attach a dragstart event that simply passes the id. As you can see, it is just a function.

Now the drop target helper:

The dropTarget is just a function that takes a callback that takes the "bull's eye" content to render anywhere in the template. It then returns the content from the callback wrapped in a div with drop and dragover event listeners attached.

When the drop event happens, we search for the element in the document and replace the target(bull's eye) with it.

Caveats

  • This example is only handling a single droppable. Make the changes to handle more
  • This example assumes access to the entire document and won't work if used inside a web component protected by a shadow root. One suggestion is to use different data transfer mechanism or a global tracking.

Besides these caveats, this example shows how much relying on the power of functions to create rich template utilities. It is just functions. Let your creativity guide you.
