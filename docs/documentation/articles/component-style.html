HTMLComponentElement Style

With Cube, style is part of the component therefore its taken care of it for you.

Cube lets you define a function for style much like the component function that also takes props. This function is called with every props update and must return a CSS string or a CSS JSON.

By default, the style is placed inside the shadow DOM. If no shadow DOM (mode of NONE), the style is placed at the head of the document.

Style function

The style function takes props and work like the component function. The few differences are:

  • The style function is called with every props update (unless not used) and the component function is only called once.
  • Style function must return a style (String or JSON format) while the component function does not need to return anything.

Below is a simple example of a JSON CSS you will learn more about later.

const MyButtonStyle = (props) => { return { ":host": { ".btn": { all: "unset", padding: "8px 20px", borderRadius: 3, textTransform: "capitalize", background: "#222", color: "#fff", letterSpacing: "0.05rem", fontFamily: "sans-serif", opacity: props.disabled() ? "0.5" : "1" cursor: props.disabled() ? "not-allowed" : "pointer" } } }; }

The style of a component must also be registered along with the component.

register(MyButton, MyButtonDefaultProps, MyButtonStyle)

Style props

The style props is in the same format as component props. Its is a map a getter keys.

Cube will try to check if the style function is using the props and call the function with every update, otherwise it will only get called once.

Another advantage would be auto complete and syntax highlight from IDEs and code editors around javascript objects. This might be important to you.

JSON CSS

JSON CSS is an option of styling format provided by Cube which comes with all benefits of JSON format. It is actually much easier to extend than CSS, and that's perhaps its top advantages.

The format is simple, any CSS selector can be an object key and the body of the object is the CSS style declaration

Nesting CSS

CSS still has limited support for nesting. If this feature is something you want to take advantage off, using JSON CSS is the best way.

& symbol

The & symbol is used for nesting. For example, this:

".parent": { "& .child" {} }

becomes:

.parent .child {}

It works just like sass ampersand symbol, and you can learn more about it in this article.

Grouping style

You can use commas to separate selector to group them much like native CSS.

".demo .lg.triangle, .demo .lg.square": { ... }

CSS String

HTMLComponentElement style function can be just return the normal CSS string.

.demo .lg:is(.triangle, .circle) { opacity: .25; filter: blur(25px); }

To trigger IDEs or code editor CSS style syntax highlight and autocomplete, you can consider wrapping it in a style tag.

Whatever is possible in CSS is okay to use. Cube puts no limitation on how CSS is handled or parsed.

External CSS

Nice enough, you can also have external CSS which is really an amazing feature. You can provide as many external styles as you want and Cube will handle it no problem.

Believe it or not, external stylesheet is just a stylesheet link

const MyComponentStyle = () => { return `` } const MyComponent = () => { template`my component` } register(MyComponent, {}, MyComponentStyle);

You may also use the import statement

const MyComponentStyle = () => { return `` }

This works even inside shadow root. Cube will move these declarations to the head tag if no shadow root is available.

This is because external stylesheets can also be handled by the shadow root stylesheets. Cube is simple handling the placement and parsing of these declarations behind the scenes. No magic here, just native browser stuff.

Host Styling

We recommend you always start your style declaration with the :host selector. This is because in case the component does not have a shadow root, Cube can change them to the component name so the style can still work. Without it, if is possible to introduce global CSS conflicts.

const MyButtonStyle = (props) => { return { ":host": { ... } }; } const MyButtonStyle = (props) => { return ` `; }

Any syntax around :host is valid, and will target the component host as promised.

You should only dismiss it if you know for sure the component will always have a shadow root which is like so by default.

One quick tip would be to change the host component display. By default, any component you create will be inline. If you create block components, change it accordingly.

const MyTitle = (props) => { return { ":host": { display: "block", ... } }; }

Also, many times, you don't need to wrap to content inside an element, target the host instead of adding extra markup.
