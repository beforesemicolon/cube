HTMLComponentElement Context

Cube has a built-in context system that is attached to the component instance itself. That means that context data in Cube is not global and may be made to very based on the location its used or props provided.

The context data flow is fully managed by Cube. All you need to do is define context then use it. Cube will manage all subscriptions and update component only if needed based on your configurations.

createContext

Once you have a component, you can use the createContext helper to define the context data for the component.

const MyComponent = () => { const sample = createContext("sample", 12); }

The above example creates a context named sample of value 12.

The createContext takes a name for the context which must be unique per component, followed by the data which can be anything you want.

It also takes an optional object as third argument where you can specify if the data is:

  • readonly: if the components using this context can change it or not. Defaults to TRUE
  • reactive: whether to update the component on change. Defaults to FALSE
const MyComponent = () => { const sample = createContext("sample", 12, {readonly: false, reactive: true}); }

The createContext returns the same thing as useContext. That's why you have the option to define if it is reactive or not. By default, context data will not trigger your component to update. That's why there is the onContextUpdate where you can listen to change and trigger updates.

Context data are readonly by default except where it is being created. The component that creates it can update the data freely. There could also be times when you want any component to update data and in that case the component that defines the context works as a store.

const MyComponent = () => { const sample = createContext("sample", 12); sample.update(32); }

useContext

The useContext helper is what gives component access to an ancestor component context data. However, the component must be in-context to receive the data. An error will be logged to and the component may break based on your component setup.

const OtherComponent = () => { const sample = useContext("sample"); }

The useContext also takes an optional second argument which defaults to TRUE. This options is for whether context changes should trigger component update.

const OtherComponent = () => { // disable component update on changes const sample = useContext("sample", false); template`

${sample.value}

`; }

To access the context data, you can use the value property which is a getter function you can use directly in the template.

onContextUpdate

The onContextUpdate is perfect for when you turn off the automatic component update on context change.

const OtherComponent = () => { // disable component update on changes const sample = useContext("sample", false); onContextUpdate((nameOfTheContext, newValue, oldValue) => { // handle logic }) }

It will get called for all context the component is using, so it is up to you which logic to use for each context change.
