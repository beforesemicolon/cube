Component Lifecycles

Cube offers four lifecycles for the component, and they can only be set in the component once. These lifecycles map to the native web components lifecycles but with a simpler name and usability.

Before Mounting

One thing to keep in mind is that your component function is called once before the first mounting. This means that even if your component is removed from the DOM (mount) and added again the function will not get called.

This behavior is just like a class constructor ,and it happens right before mounting.

This means that anything initialized inside the component remains regardless of component been removed from the DOM and can lead to memory leaks. Therefore, it should be used for things that remains as long as the component instance is needed.

onMount

The onMount lifecycle is called when the component is added to the DOM. It is the perfect place to start any subscription and initialize timers.

const MyComponent = () => { let interval; onMount(() => { interval = setInterval(() => { // logic }, 1000) }) }

onMount vs component body

Truth is, because the component function is called only once, you can do anything you can do inside the onMount inside the function body.

const MyComponent = () => { const interval = setInterval(() => { // logic }, 1000) }

This will work the same way because the component function is called right before the component is added to the DOM and the onMount lifecycle is called.

By using onMount you make sure things are only done when the component is mounted. There could be that the component is removed or moved to different places in the DOM or even new documents. By using the lifecycle you ensure that proper setup and cleanup is done correctly.

One additional advantage of using onMount is that it handles the mounting and unmount.

const MyComponent = () => { onMount(() => { const interval = setInterval(() => { // logic }, 1000) return () => { clearInterval(interval) } }) }

You can return a cleanup function from the onMount callback which will be called whenever the component is removed from the DOM.

onDestroy

The onDestroy lifecycle is used to cleanup anything set up during the component mounting or initialization.

const MyComponent = () => { const interval = setInterval(() => { // logic }, 1000) onDestroy(() => { clearInterval(interval) }) }

If you are using the onMount lifecycle you can simply return the destroy callback. If you use the onDestroy with the onMount destroy callback, the onDestroy takes precedence.

onAdoption

The onAdoption lifecycle is triggered when a component is moved from one document to another.

const MyComponent = () => { onAdoption(() => { // logic }) } const {tagName} = register(MyComponent); const comp = document.createElement(tagName); const iframe = document.body.querySelector('iframe'); // will trigger onMount document.body.appendChild(comp) // will trigger onAdoption then onMount iframe.contentDocument.body.appendChild(btn)

This lifecycle is useful to check if the component was moved to an environment where certain things may or may not exist to make appropriate changes.

onUpdate

The onUpdate lifecycle is particularly different as it informs you about very specific changes. It will be triggered:

  • After a prop change (either via the attribute or directly changing the property) and the DOM was updated with the change;
  • Only if the component is mounted. This does not mean the component element will not be updated;

The lifecycle callback is called exactly with the property that changed.

const MyComponent = () => { onUpdate((propName, newValue, oldValue) => { // logic }) }

Like you can see, this lifecycle does not get triggered for internal state changes, only props. This is because if there are internal states, you know when this will be changing because you set the logic.

You can use this lifecycle for internal logic, not derived states but anything you need to trigger or adjust.
